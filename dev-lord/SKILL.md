# Skill: Dev-Lord (Master Software Lifecycle Wizard)

## Purpose & Philosophy
**Dev-Lord** is the unified master skill for end-to-end software engineering. It navigates requests through five interconnected roads:
- **Road A (Greenfield Spec Architect):** Passive idea ingestion followed by structured advisory, producing a tech-stack-agnostic Master Specification.
- **Road U (UI Prototype Architect):** Turns a spec into a verified, working HTML prototype either from a local commercial/open-source theme (via automated subagent ingestion) or via AI-crafted modern design. Serves as a **strict read-only design source of truth** for subsequent implementation.
- **Road B (Re-Platform & Migration Architect):** Deep hidden-logic discovery, dynamic avoid-lists, and baseline parity sample capture for zero-regression migrations.
- **Road C (Gated Execution Engine):** Grounded, file-persisted implementation in `.devop-process/` with bidirectional traceability, atomic task sizing ($\le$ 5 files), feature branch isolation, live verification, and an express **Lite track**.
- **Road D (Session Resume & Recovery):** Fast-boot re-entry into in-flight tasks from file state with zero context amnesia.

## Operating Principles (Non-Negotiables)
1. **The Session is a Resource, Not a Container:** When context degrades (40+ turns, re-reading files, or large content dumps), save state to disk and execute the Session Handoff Protocol.
2. **Every Decision is User-Confirmed or File-Read:** State lives exclusively on disk in `.devop-process/`. Never rely on chat memory alone.
3. **Execution Over Assertion:** A task is never complete without running the real terminal command, test suite, or HTTP check. Reading code back is NOT verification.
4. **Silence is Not Approval:** Never bypass a hard gate (Clarification, Plan, Constitution) on assumption or "reasonable defaults."
5. **Strict Avoid-Lists:** Technical selections immediately generate counter-defaults in `constitution.md` to prevent architectural drift.
6. **Decompose First:** Bundled requests must be decomposed into isolated requirements before planning or coding.
7. **Proportional Rigor:** Small, well-scoped changes (1–3 files) use the express Lite track; complex work uses Full Track Road C.
8. **Atomic Revert Safety & Feature Isolation:** Verify a clean worktree before coding. Use pre-edit snapshots (`.devop-process/.snapshots/`) if Git is absent. Full Track tasks are isolated on a dedicated feature branch (`feature/<name>`). Revert immediately on failed verification using targeted file restores only.
9. **Informed Approval via Structured Options:** Present decisions with labeled options: **[A] Recommended**, **[B] Lighter/Minimal**, **[C] More Robust**, **[D] Custom**.
10. **Risk-Proportional Scrutiny:** Work touching auth, payments, permissions, data deletion, or external APIs is tagged `RISK: HIGH` and requires mandatory test coverage.
11. **Honest Framing:** Deliverables are described accurately as *"Verified & Runnable"* (Full Rigor) or *"Implemented & Code-Reviewed"* (Reduced Rigor) rather than "production ready" unless production hardening was completed.
12. **UI Prototype as Strict Read-Only Design Source:** The prototype generated by Road U is an immutable design specification. Road C recreates its screens natively in the chosen stack (React, Django, etc.) and must **never** modify or wire runtime code directly into the prototype HTML files.
13. **YAGNI (No Speculative Scope):** Implement only what the current task's acceptance criterion requires. No unrequested hooks or abstractions.
14. **Spec–Prototype Sync Integrity:** The Master Spec and the UI Prototype are two views of the same truth. During Road U, whenever a Spec of Record exists, any spec-relevant change to the prototype must be reconciled into the spec with user approval (Step U7-R), and prototype delivery is blocked until the sync audit passes (Step U13-S). If the user has no written spec, the sync is marked N/A and does not interrupt the run.
15. **Hierarchical Subagent Delegation (with Single-Context Fallback):** The Main Agent is the persistent Project Manager and the sole user guide. Subagents are stateless workers dispatched for isolated tasks (theme ingestion, screen generation, atomic task implementation) that report factual evidence and terminate immediately. **Fallback:** If subagent dispatch is unavailable or unsupported in the host environment, the Main Agent executes the task directly in the current context (reading target files, editing, running verification, logging to disk) while minimizing context overhead.
16. **Skill Path Resolution Protocol:** At session boot, the Main Agent resolves `<SKILL_DIR>` to the absolute directory containing `SKILL.md`. All internal references to `<SKILL_DIR>/roads/`, `<SKILL_DIR>/templates/`, or `<SKILL_DIR>/references/` must use this resolved absolute path to guarantee portability when Dev-Lord is executed across arbitrary external workspaces.
17. **Repository Initialization & Git Negotiation Protocol:** Prior to code implementation or task execution (Road C, Road C-Lite, Road D), verify version control availability:
    - **Check Repo:** Test if the workspace is an active Git repository (`git rev-parse --is-inside-work-tree` or test for `.git` directory).
    - **If already a Git repo:** Proceed with standard Git branch isolation and atomic commit workflows.
    - **If NOT a Git repo:**
      1. Check if the `git` CLI command is installed (`git --version`).
      2. **If `git` is installed:**
         - Automatically initialize a new repository: `git init`.
         - Stage existing files and create initial baseline commit: `git add . && git commit -m "chore: baseline initial workspace state"`.
         - Inform user: *"Initialized Git repository with baseline workspace commit."* Proceed with standard Git workflow.
      3. **If `git` is NOT installed:**
         - Prompt the user for permission:
           > *"Git is required for atomic version control, verification reverts, and safe checkpoints, but the `git` command was not found in your environment. May I install `git` (e.g. via winget/brew/apt) and initialize a repository?*
           > - **[1] Yes, install git and initialize repository**
           > - **[2] No, use snapshot mode (directory-based backups)"*
         - **If user approves:** Install `git` using the host package manager (`winget install --id Git.Git -e --source winget` on Windows, `brew install git` on macOS, `apt-get install -y git` on Linux), verify installation, execute `git init`, create baseline commit, and proceed with Git workflow.
         - **If user refuses (or install fails):** Fallback to **Snapshot Mode**. Store pre-task snapshots under `.devop-process/.snapshots/task-NN/`, execute targeted reverts by copying back from snapshots, set `Active Working Feature Branch: N/A (Snapshot Mode)`, and bypass all Git commands.

## Trigger Conditions
Activate immediately when user intent matches:
- **Greenfield / Concept:** *"I have an idea for an app..."*, *"Help me spec out..."* $\rightarrow$ **Road A**
- **UI Prototyping:** *"Prototype the UI..."*, *"Build screens from theme..."*, *"Create mockups..."* $\rightarrow$ **Road U**
- **Migration / Porting:** *"Migrate my app from X to Y..."*, *"Rewrite this project in..."* $\rightarrow$ **Road B**
- **Active Implementation / Bug Fix:** *"Build feature X..."*, *"Fix bug Y..."* $\rightarrow$ **Road C (Full or Lite)**
- **Continuation:** *"Continue working on..."*, *"Resume task..."* $\rightarrow$ **Road D**

*Do NOT activate for pure conceptual explanations or micro-typo fixes where the user explicitly requests skipping process.*

## Step 0: Boot, Intent Fast-Path & Classification

Upon invocation, execute the boot triage sequence:

### 1. Intent Fast-Path Check
If the user's initial prompt contains an unambiguous, specific directive matching an existing state or road:
- **Resume Directive** (*"continue task T002"*, *"resume work"*): Confirm in one line (*"Resuming active work via Road D..."*) and dispatch directly to **Road D**.
- **UI Prototyping Directive** (*"prototype UI"*, *"build screens from theme"*): Confirm in one line (*"Launching UI Prototyping via Road U..."*) and dispatch directly to **Road U (Step U0)**.
- **Migration Directive** (*"migrate my app from X to Y"*): Confirm in one line and dispatch directly to **Road B (Step B1)**.
- **Greenfield Directive** (*"spec out an idea"*, *"new app concept"*): Confirm in one line and dispatch directly to **Road A (Phase A1)**.
- **Small Bug Fix / Tweak** (*"fix typo in button"*, *"small bug in file.js"*): Confirm in one line, verify scope (1–3 files), and dispatch directly to **Road C-Lite (Step L1)**.

### 2. If `.devop-process/` Exists (and Intent Was Ambiguous)
1. **Kernel Completeness Check:** Verify that all 6 state files exist in `.devop-process/` (`constitution.md`, `spec.md`, `plan.md`, `tasks.md`, `decisions.md`, `progress-log.md`). If any file is missing, seed it immediately from `<SKILL_DIR>/templates/` with its Current Summary header populated.
2. Read `constitution.md` and the Current Summary of `progress-log.md`. Prompt the user:
   > *"I detected an active project state in `.devop-process/`. Last recorded task: [Task ID: Title].*
   > *How would you like to proceed?*
   > - **[1] Resume active work** $\rightarrow$ Dispatch to **Road D**
   > - **[2] Add a new feature / report a bug** $\rightarrow$ Ask Scope Question Q1 below
   > - **[3] Start fresh activity** $\rightarrow$ Proceed to Question Q0 below."*
3. If **[2]** is chosen, ask **Scope Question Q1**:
   > *"Roughly how big is this change?*
   > - **[1] Small & isolated** (touches ~1–3 files, no architecture/auth impact) $\rightarrow$ **Road C-Lite**
   > - **[2] Medium or large** (multi-file, schema, auth, or ambiguous scope) $\rightarrow$ **Road C (Step C3)**"*

### 3. If `.devop-process/` Does Not Exist
1. **Workspace Artifact Auto-Discovery:**
   - **If `ui-prototype/` exists:** Inspect `ui-prototype/.prototype-state.json` (or screen files). Ask:
     > *"Detected existing UI prototype at `./ui-prototype/`. How would you like to proceed?*
     > - **[1] Resume or add prototype screens** $\rightarrow$ **Road U**
     > - **[2] Select stack & implement natively** $\rightarrow$ **Road C (Step C1 & C2)**
     > - **[3] Start other activity** $\rightarrow$ Proceed to Question Q0 below."*
   - **If `MASTER_SPEC.md` exists:** Ask:
     > *"Detected finalized specification `MASTER_SPEC.md`. How would you like to proceed?*
     > - **[1] Prototype UI first** $\rightarrow$ **Road U (Step U0)**
     > - **[2] Select stack & implement** $\rightarrow$ **Road C (Step C2)**
     > - **[3] Start other activity** $\rightarrow$ Proceed to Question Q0 below."*
   - **If `ANALYSIS.md` & `CONVERSION_PLAN.md` exist:** Ask:
     > *"Detected migration blueprint. How would you like to proceed?*
     > - **[1] Prototype UI first** $\rightarrow$ **Road U (Step U0)**
     > - **[2] Execute live migration** $\rightarrow$ Seed `.devop-process/` from `ANALYSIS.md` & `CONVERSION_PLAN.md` (per Road B [BX-2]), execute Clean Baseline Test Check, then enter **Road C (Step C6)**
     > - **[3] Start other activity** $\rightarrow$ Proceed to Question Q0 below."*
   - **If `MIGRATION_PROMPT.md` exists:** Ask:
     > *"Detected exported migration package `MIGRATION_PROMPT.md`. How would you like to proceed?*
     > - **[1] Execute live migration** $\rightarrow$ Extract blueprint, seed `.devop-process/` (per Road B [BX-2]), execute Clean Baseline Test Check, then enter **Road C (Step C6)**
     > - **[2] Prototype UI first** $\rightarrow$ **Road U (Step U0)**
     > - **[3] Start other activity** $\rightarrow$ Proceed to Question Q0 below."*
2. **If no active state or recognized artifacts exist, present Wizard Question Q0:**
   > *"Welcome to Dev-Lord. What are you looking to accomplish today?*
   > - **[1] Greenfield Project / New Idea**: I have an idea or requirements, but no code yet $\rightarrow$ **Road A**
   > - **[2] Re-Platform / Migrate Existing App**: Port a working app from Stack X to Stack Y $\rightarrow$ **Road B**
   > - **[3] Implement, Fix, or Refactor**: Write, test, and verify code right now $\rightarrow$ Ask Scope Question Q1
   > - **[4] Ready Spec**: I have a complete spec ready; write to `.devop-process/` and build $\rightarrow$ **Road C (Step C2)**
   > - **[5] Prototype UI (Theme or AI-Crafted)**: Generate real HTML screens as a design source of truth $\rightarrow$ **Road U (Step U0)**"*
